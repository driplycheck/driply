Telegram Mini App для шаринга образов с внутренней валютой «дрипы» (💧).
Бот: `t.me/Driplycheckbot` · Репозиторий: `github.com/driplycheck/driply`

## Критические правила

### Пуш
Только через скрипт, который лежит **вне репозитория**:
```bash
~/Documents/driply_push.sh "commit message"
```
Он делает: ESLint (warnings, не блокирует) → `npm run build` (блокирующий гейт) → commit → push.
Никогда не пушить вручную `git push` в обход скрипта.

### После пуша
Проверить статус деплоя на Vercel (**Ready**, не Building и не Error) **до** теста в Telegram. Иначе тестируешь старую версию и делаешь ложные выводы.

### Известные ESLint warnings
5 штук (`exhaustive-deps` в BlockedList/PostsArchive/Profile, неиспользуемые `share` и `inviteFriend`). Это норма, не паниковать.

## Архитектура бэкенда

### Единый роутер
Фронт **никогда не пишет в базу напрямую**. Все write-операции идут через одну Edge Function:

```js
supabase.functions.invoke('quick-handler', {
  body: { action: 'set_follow', initData: getInitData(), ... }
})
```

`quick-handler` валидирует подпись Telegram `initData`, достаёт `tgUser.id`, и зовёт RPC через `SERVICE_ROLE_KEY`.

Деплой функции: `supabase functions deploy quick-handler`

### Права на RPC
- **Write-функции** (`create_post`, `set_profile`, `cast_vote`, `delete_post`, `set_follow`, `set_block`, `report_*`, `mod_*` и т.д.) — доступны **только service_role**. Публичные роли отозваны намеренно: иначе любой мог дёрнуть `/rest/v1/rpc/create_post` с чужим `p_tid` и действовать от чужого имени в обход проверки initData.
- **Read-функции** (`main_feed`, `following_feed`, `my_profile`, `top_users`, `search_people`, `profile_relations`, `follow_list`, `my_posts`, `my_votes`, `my_blocks`, `ref_stats`, `ref_invited_list`, `posts_by_style`) — доступны anon, их фронт зовёт напрямую через `supabase.rpc(...)`.

Если добавляешь новую write-RPC — сразу отзови права у публичных ролей:
```sql
revoke all on function public.new_fn(args) from public, anon, authenticated;
grant execute on function public.new_fn(args) to service_role;
```

### Колонки users
С публичного ключа читаются только: `id, username, avatar_url, style_score, created_at, display_name, bio, hide_username, is_founder, badge, gender, allow_dm`.

**Не читаются**: `telegram_id`, `notify_prefs`, `referred_by`, `ref_rewarded`, `ref_code`, `last_story_reward`, `daily_credits`. Свой профиль грузится через RPC `my_profile(p_tid)`.

Если новому экрану нужны эти поля — не открывать грант, а добавить RPC.

### Соглашения RPC
- Все функции принимают **`p_tid` (telegram_id)**, а не внутренний `id`. Внутри резолвят: `select id from users where telegram_id = p_tid`.
- Все `security definer` функции обязаны иметь `set search_path to 'public'`.

## Грабли, на которые уже наступали

- **`set_referrer_code` вызывает `set_referrer`.** Не удалять одну без другой — реферальная система ломается молча.
- **Перед удалением любой SQL-функции** проверить, не зовут ли её другие функции внутри базы:
  ```sql
  select proname from pg_proc where prosrc ilike '%имя_функции%';
  ```
  Grep по коду приложения этого не покажет.
- **`supabase/schema.sql` может отставать от реальной базы.** Источник истины — прод. Не доверять файлу вслепую.
- **`supabase db dump` требует Docker.** Без него команда падает, но **успевает обрезать файл** — легко закоммитить пустышку.
- **Реферальное окно закрывается навсегда**, если `set_referrer` не отработал до первого поста юзера (`not_new`).
- **JSX-патчи скриптом**: следить, чтобы вставка попадала внутрь возвращаемого дерева, а не после закрывающего тега. Дважды ловили `Expected ")" but found "{"`.
- **zsh + grep**: маску в кавычки — `--include='*.jsx'`, иначе `no matches found`.

## Модерация

```sql
select * from moderation_queue;   -- очередь, сортировка по числу жалоб на юзера
select mod_uphold(<report_id>);   -- согласиться: скрыть пост + закрыть жалобы
select mod_dismiss(<report_id>);  -- отклонить как необоснованную
```

Репорт-флоу работает в трёх местах: лента (`PostCard`), открытый пост (`PostView`), профиль (`Profile`). Общий компонент — `ReportModal.jsx`. Пожаловавшийся больше не видит этот пост (предикат `has_reported` в обеих лентах).

`reports` — единственная таблица **без политики чтения**, это намеренно. Жалобы не должны быть доступны с клиента.

## Экономика

- Старт: 200 💧
- Первый пост: +300 💧, последующие: +100 💧
- Реферал: пригласившему +500 💧, новичку +200 💧 — **только после первого поста новичка**, флаг `ref_rewarded` защищает от повтора
- История в Stories: +200 💧, раз в сутки (`last_story_reward`)
- Голос: списывается у голосующего, автору идёт в `style_score`
- Дрипы **нельзя купить за деньги** — намеренно, иначе рейтинг обесценивается

## Стадия продукта и приоритеты

Продукт технически готов больше, чем требует текущая стадия. Узкое место — не код, а отсутствие пользователей и данных по удержанию.

Это значит: **предложение «давай добавим фичу» почти всегда хуже, чем «давай доведём то, что влияет на первое впечатление»** — карточка образа, стартовое сообщение бота, путь до первого поста.

Исключение, где работа над продуктом оправдана до роста: **визуальное качество.** Продукт про внешний вид, аудитория 14-21 судит по скриншоту. Приложение, которое само выглядит средне, не может убедительно оценивать чужой стиль.

Следующий реальный шаг по плану — 20-30 живых пользователей и данные: откуда пришли, возвращаются ли, что зацепило.
